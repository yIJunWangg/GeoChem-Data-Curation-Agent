# 映射确认 → 人工审核 → 溯源 → 标准化导出 全链路设计

## 问题根源

Web 工作台使用 `candidate_records` + `candidate_cells` 数据模型，与旧管线的 `field_mappings` → `review_items` → `standardized_records` 完全断开。确认按钮只改状态标记，不产生规则、不触换单位换算、不生成标准化记录。

## 数据流设计

```
候选表 (candidate_cells)
  ↓ 确认映射
规则写入 mapping_rules + MemoryStore
  ↓ 单位不一致时
计算换算 → calculation_records
  ↓ 人工审核通过
standardized_records（含 element_id + bbox 溯源）
  ↓
溯源页展示 + 标准化导出
```

## 修改 1：映射与确认（工作台 Step 3）

### 1a. 确认按钮写入规则

**文件**: `src/geochem/workbench_service.py`

新增方法 `confirm_cell_mapping(project_id, cell_id, user_overrides)`:
- 读取 `candidate_cells` 原始值、原始单位、目标字段、目标单位
- 更新 `candidate_cells.mapping_status = 'confirmed'`, `review_status = 'confirmed'`
- 如果单位不一致且有换算公式，自动执行换算并写入 `calculation_records`
- **规则写入逻辑**：
  - 用户直接确认 LLM 建议 → **不写入规则记忆**（LLM 的建议不需要沉淀）
  - 用户修改了目标字段/单位/公式 → **写入规则记忆**（用户的专业判断需要沉淀）
  - 写入时同时保存两种格式：
    - `mapping_rules` 表（机器读取，用于自动匹配）
    - `memory/rules.md`（Agent 读取，人类可审查）

**文件**: `src/geochem/web/api.py`

新增端点 `POST /api/v1/candidate-cells/{cell_id}/confirm`:
```python
class CellConfirmRequest(BaseModel):
    target_field: str | None = None
    target_unit: str | None = None
    formula: str | None = None
    conversion_factor: float | None = None
    # 不需要 save_as_rule —— 系统自动判断：用户修改了才写入
```

### 1b. 自动应用已有规则

**文件**: `src/geochem/workbench_service.py`

在 `create_extraction_batch` 中，`_merge_record` 写入 cell 后：
- 查询 `mapping_rules` 表中是否有匹配的 `(source_field, target_field)` 或 `(source_unit, target_unit)` 规则
- 如果有，自动应用换算，标记 `mapping_status = 'auto_applied'`，附注 `rule_id`
- 在 UI 中显示"人工确认"标签

**规则读取时机**（全链路）：
1. **资源发现** (`discover_article`): LLM prompt 注入 `memory/rules.md` 内容，让 Agent 知道需要识别哪些专业术语
2. **表头数据抽取** (`create_extraction_batch`): `_merge_record` 查询 `mapping_rules` 自动匹配换算
3. **映射确认** (Step 3): 已匹配规则的 cell 显示"自动应用 · 人工确认"
4. **人工审核** (Review): 规则匹配的 cell 置信度更高，优先通过

### 1b2. 规则记忆双格式

**文件**: `src/geochem/workbench_service.py`

规则写入时同时保存两种格式：

1. **`mapping_rules` 表**（机器读取）：供 `_merge_record` 和 `create_extraction_batch` 自动查询匹配
2. **`memory/rules.md`**（Agent / 人类读取）：Markdown 格式，每条规则一段，包含：
   - 规则来源（用户修改 / 人工填表 / OCR 框选）
   - 原始字段 → 目标字段
   - 换算公式和因子
   - 适用条件
   - 创建时间

示例 `memory/rules.md`：
```markdown
## MAP_NA2O_TO_NA_001
- 来源: 用户在映射确认中修改了目标字段
- 原始字段: Na2O
- 目标字段: Na
- 原始单位: wt%
- 目标单位: wt%
- 公式: Na = Na2O × 0.741857
- 因子: 0.741857
- 适用: 所有 Na2O → Na 的换算
- 创建: 2026-06-23

## EXTRACT_SST_001
- 来源: 人工在 PDF 框选补充
- 目标字段: SST
- 说明: Sea Surface Temperature，LLM 未识别的专业缩写
- 识别规则: 正文中出现 "SST" 且附近有 "°C" 或 "℃"
- 创建: 2026-06-23
```

Agent 在做抽取和资源发现时，先读取 `memory/rules.md` 作为上下文 prompt 的一部分。

### 1c. 前端映射确认交互改造

**文件**: `web/src/WorkbenchPage.tsx` — `MappingReview` 组件

重写为：
- 左侧：待确认映射列表（每行显示：原始字段 → 目标字段、单位、值、风险等级）
- 点击某行 → 右侧展开详情面板：
  - 原始值 / 目标值
  - 原始单位 / 目标单位
  - **换算公式**：系统先调用 LLM 推荐公式（如 `Na = Na2O × 0.741857`），用户可修改
  - 转换因子（自动从公式解析，可手动调整）
  - 确认/跳过按钮
  - **不需要"保存为规则"复选框** —— 系统自动判断：用户修改了 LLM 建议才写入规则
- 已有规则自动匹配的行显示"自动应用 · 人工确认"标签

**LLM 换算建议流程**:
1. 用户点击待确认映射行
2. 前端调用 `POST /api/v1/candidate-cells/{cell_id}/suggest-conversion`
3. 后端用 LLMClient 发送 prompt: "原始字段 X (单位 A) → 目标字段 Y (单位 B)，请给出换算公式和因子"
4. LLM 返回 `{ formula: "Na = Na2O × 0.741857", factor: 0.741857 }`
5. 前端填充到公式/因子输入框，用户可修改
6. 用户确认后调用 `POST /api/v1/candidate-cells/{cell_id}/confirm`

**文件**: `web/src/api.ts`

新增：
```ts
confirmCell: (projectId, cellId, payload) => POST /api/v1/candidate-cells/{cellId}/confirm
```

## 修改 2：人工审核页面重设计

### 2a. 页面布局

**文件**: `web/src/Pages.tsx` — 重写 `ReviewPage`

两栏布局：
- **左侧 (60%)**: 候选表格（AG Grid），显示当前文章所有 candidate_records
  - 按 sample_id 排序
  - 单元格颜色：绿色=已确认、黄色=待审核、红色=冲突、灰色=缺失
  - 点击任意单元格 → 触发右侧 PDF 跳转
- **右侧 (40%)**: PDF 查看器 + 元素位置工作台
  - 顶部：PDF 页面渲染（react-pdf），自动跳转到选中单元格的 `page_number`
  - 在 PDF 上高亮该单元格对应的 `bbox` 区域（蓝色半透明叠加）
  - 底部：该单元格的详细信息（原始值、单位、置信度、来源元素、冲突候选）

### 2b. 审核操作

**逐行审核**（一行 = 一个样品）：
- 每行左侧有复选框，可选中多行
- 选中行后点击"批量通过"→ 整行所有单元格 `review_status = 'approved'`
- 也可以展开某行，查看该行每个单元格的详情：
  - 原始值、目标值、单位、置信度、风险等级
  - 冲突候选（如果有 alternatives）
  - 单个单元格可单独：通过 / 修改值 / 拒绝
- 行级操作：
  - **通过**: 该行所有 confirmed 单元格进入标准化
  - **修改**: 在 AG Grid 中直接编辑单元格值
  - **拒绝**: 该行不进入标准化（整行标记为 rejected）
  - **批量通过**: 选中多行一键通过

### 2b2. 人工框选补充（LLM 缺失时）

当 LLM 抽取遗漏了某些字段（特别是专业术语），用户可以在 PDF 上框选补充：

**操作流程**:
1. 用户发现候选表中某行某列为空（如 "SST" 列，LLM 未识别这个缩写）
2. 用户在右侧 PDF 上拖拽框选对应区域
3. 系统 OCR 读取框选内容（调用 `_render_region` + LLM 识别）
4. 弹出填表面板：
   - **目标表头**: 下拉选择（如 "SST"）
   - **OCR 识别值**: 自动填充，可修改
   - **单位**: 自动推测或手动填写
   - **说明**: 用户填写为什么需要这个值（如 "SST = Sea Surface Temperature，正文中第 X 段提到"）
5. 确认后：
   - 值写入对应 `candidate_cells`
   - **写入规则记忆**（`mapping_rules` 表 + `memory/rules.md`）：
     - 规则类型: `extraction_hint`
     - 内容: "SST" 是 Sea Surface Temperature 的缩写，抽取时需识别
   - 下次抽取时，Agent 读取 `memory/rules.md`，自动识别 SST 字段

**后端端点**:
- `POST /api/v1/articles/{article_id}/manual-fill` — 框选补充
  - 参数: `resource_id, page_number, bbox, target_header, value, unit, explanation`
  - 逻辑: OCR → 写入 candidate_cells → 写入 extraction_rules → 写入 rules.md

**前端**:
- PDF 工具栏增加"补充填表"模式
- 框选后弹出填表面板（目标表头下拉 + OCR 值 + 单位 + 说明）
- 确认后候选表实时更新

### 2c. 后端

**文件**: `src/geochem/web/api.py`

新增端点：
- `GET /api/v1/articles/{article_id}/candidate-records` — 返回该文章所有 batch 的候选记录（含 cells）
- `POST /api/v1/candidate-records/{record_id}/approve` — 行级审核通过
- `POST /api/v1/candidate-records/{record_id}/reject` — 行级审核拒绝
- `POST /api/v1/articles/{article_id}/batch-approve` — 批量行级通过
- `POST /api/v1/candidate-cells/{cell_id}/suggest-conversion` — LLM 换算建议

**文件**: `src/geochem/workbench_service.py`

新增方法：
- `approve_record(project_id, record_id)` — 行级通过（该行所有 confirmed cells → approved）
- `reject_record(project_id, record_id)` — 行级拒绝
- `batch_approve_records(project_id, record_ids)` — 批量行级通过
- `suggest_conversion(project_id, cell_id)` — 调用 LLM 推荐换算公式
- `article_candidate_records(project_id, article_id)` — 查询该文章所有候选记录

## 修改 4：标准化导出

### 4a. 审核通过 → 生成标准化记录

**文件**: `src/geochem/workbench_service.py`

新增方法 `finalize_standardized(project_id, article_id)`:
- 遍历该文章所有 `review_status = 'approved'` 的 candidate_records
- 每条 record 生成一条 `standardized_records`
- 写入 `data` JSON（按用户表头组织）
- 写入溯源字段：`original_fields`, `original_values`, `mapped_fields`, `confidence_scores`, `review_statuses`
- 关联 `element_id` 和 `bbox` 信息到溯源字段
- 设置 `quality_grade`（A=直接匹配, B=规则映射, C=换算, D=待确认）

**文件**: `web/src/Pages.tsx` — 改造 `StandardizedPage`

- "导出 CSV" / "导出 XLSX" 按钮 → 调用后端导出
- "导出审计包"按钮 → 生成完整审计目录

### 4c. 后端

**文件**: `src/geochem/web/api.py`

## 验证

1. **映射确认 + 规则写入**: 在 Step 3 确认一个单位不一致的映射（如 Na2O wt% → Na wt%），LLM 建议公式 → 用户直接确认 → 检查 `mapping_rules` 表**无**新记录（LLM 建议不沉淀）
2. **用户修改 + 规则写入**: 用户修改 LLM 建议的公式 → 检查 `mapping_rules` 表有新记录 + `memory/rules.md` 有对应条目
3. **规则自动应用**: 再次抽取同类型数据，确认该规则被自动应用，显示"自动应用 · 人工确认"标签
4. **人工框选补充**: 在审核页发现 LLM 遗漏的字段 → 在 PDF 上框选 → OCR 读取 → 填写说明 → 确认 → 检查候选表更新 + rules.md 有新 extraction_hint 规则
5. **审核 → 溯源**: 审核通过若干条目 → 进入溯源页 → 确认每条记录显示完整溯源链和 PDF 位置高亮
6. **标准化导出**: 进入标准化导出页 → 确认审核通过的条目出现 → 点击导出 CSV → 验证文件内容正确
7. **规则记忆页**: 确认新规则显示"人工确认"标签，来源标注正确
